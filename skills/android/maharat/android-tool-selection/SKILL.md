# Android Tool Selection

ابدأ بجرد الموجود في دليل البيئة: ADB Wireless وAppium/UiAutomator2 وpytest وPillow وSupervisor وGitHub Actions. لا تضف أداة تؤدي الوظيفة نفسها إلا إذا أثبتت تجربة قصيرة أنها أفضل أو تسد فجوة واضحة.

## قرار الاختيار

- التحكم الدلالي: Appium/UiAutomator2 أولًا؛ طبقة وكيل واحدة فقط عند الحاجة.
- الألعاب وCanvas: coordinate actions مع OpenCV أو native-ai-tester/Airtest بعد اختبار الثبات.
- OCR: Tesseract أولًا؛ لا تضف PaddleOCR أو EasyOCR إلا بعد قياس فشل العربية أو النص الصغير.
- الأداء: Perfetto أولًا؛ لا تضف AGI أو Battery Historian إلا لحالة مثبتة.
- الأمن: mobsfscan وMobSF لمسار APK مصرح؛ Frida في مختبر منفصل فقط.
- التقارير: اختر pytest-html أو Allure، لا الاثنين مبدئيًا.

## فحص المصدر

تحقق من المستودع الرسمي، commit محدد، LICENSE، SECURITY.md إن وجد، ونطاق الصلاحيات. استبعد الملفات التنفيذية غير الضرورية والـsecrets والـ`.env`. افحص السكربت قبل تشغيله ولا تنفذ install script من الإنترنت مباشرة؛ نزّل المصدر، راجعه، ثم شغّل أقل أمر لازم.

## التثبيت والتحقق

ثبّت داخل Debian أو Python venv أو Node workspace المناسب، لا في النظام العالمي بلا سبب. بعد التثبيت شغّل `--version` وdoctor وsmoke test غير مدمر. سجّل الإصدار والمصدر والنتيجة، واجعل الرجوع ممكنًا بإزالة الحزمة أو حذف البيئة المؤقتة.

## حدود الوكيل

التثبيت والتجربة مسموحان داخل بيئة الاختبار. لا تثبت خادمًا يفتح منفذًا عامًا، ولا ترسل بيانات الهاتف إلى خدمة خارجية، ولا تستخدم أدوات تجاوز الحماية خارج تطبيق/حساب مصرح به.
