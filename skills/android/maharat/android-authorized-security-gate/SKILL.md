# Android Authorized Security Gate

لا تبدأ اختبارًا أمنيًا إلا إذا كان APK أو المصدر أو الجهاز داخل نطاق مكتوب ومخصص للاختبار. هذه المهارة لا تمنح تفويضًا؛ هي تتحقق من وجوده.

## بوابة البدء

تحقق من اسم التطبيق وpackage ونسخة APK وSHA256 والجهاز/المحاكي وحساب الاختبار ومدة الاختبار. ارفض ملفات الإنتاج أو بيانات المستخدم أو الأجهزة غير المدرجة في النطاق. احتفظ بنسخة أصلية للقراءة فقط.

## اختيار الأداة

ابدأ بتحليل ساكن محدود و`mobsfscan` أو MobSF على نسخة اختبارية. استخدم Frida فقط في مختبر مصرح وبنسخ متطابقة من host وserver. لا تستخدم bypass أو hooks أو استخراج أسرار إلا عندما ينص نطاق الاختبار صراحة على ذلك، ولا تحاول تجاوز ضوابط خادم حقيقي أو Play Integrity حقيقي.

## أوامر خطرة

اعتبر `pm clear` و`uninstall` و`reboot` و`adb pull` من مسارات البيانات الخاصة وتعديل النظام. لا تنفذها تلقائيًا. أوقف العملية إذا طلبت أداة حذف ملفات أو فتح منفذ عام أو رفع بيانات إلى خدمة خارجية. راجع كل install script قبل تشغيله؛ لا تشغّل `curl | bash` من مصدر غير محفوظ ومراجع.

## التقرير

سجل نطاق التفويض، الأداة والإصدار، commit المصدر، SHA256، الأوامر المنفذة، النتائج، وحدود الاختبار. نقّح tokens وserial وIMEI والبيانات الشخصية. افصل التقرير الأمني عن تقارير اختبار المنتج، ولا ترفع الأدلة الحساسة إلى Git.
