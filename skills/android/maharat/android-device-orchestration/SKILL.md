# Android Device Orchestration

استخدم مسار تحكم واحدًا في الجلسة: Appium/UiAutomator2 للتطبيقات ذات شجرة الواجهة، أو ADB/coordinate actions للألعاب وCanvas، أو طبقة وكيل واحدة مثل agent-device أو native-ai-tester. لا تشغّل محركي UiAutomation متنافسين في الوقت نفسه.

## قبل أي إجراء

1. افحص `adb devices -l`، و`agentctl status`، وحالة Appium.
2. طابق serial أو عنوان الجهاز مع allowlist الخاصة ببيئة الاختبار.
3. احصل على قفل الجهاز قبل ADB أو Appium أو scrcpy.
4. تحقق من package تحت الاختبار ونسخة APK وGit commit.
5. أنشئ مجلد أدلة فريدًا للاختبار.

## سياسة التشغيل

يسمح بالتثبيت والتجربة والتكرار داخل جهاز/محاكي وAPK مصرح بهما. لا تنفذ `reboot` أو `pm clear` أو إزالة تطبيق أو تغيير إعدادات النظام أو `pull/push` لملفات خاصة إلا إذا كانت بيئة الاختبار والـallowlist تسمح بذلك؛ عند الشك توقف وسجل السبب. لا تفتح ADB أو Appium أو Supervisor على الإنترنت.

## التفاعل

ابدأ بالـaccessibility snapshot أو UI dump. إذا لم توجد عناصر موثوقة، استخدم Screenshot وتحليلًا بصريًا ثم إحداثيات مطبّعة، مع التحقق من orientation وresolution وinsets. بعد كل فعل مهم التقط حالة جديدة وتحقق من النتيجة؛ لا تفترض نجاح اللمسة.

## التثبيت الذاتي

عند غياب أداة، افحص الإصدار والترخيص ومصدر التثبيت أولًا. ثبّت أقل مكوّن يحقق الحاجة داخل البيئة الافتراضية أو workspace المؤقت، ثم شغّل doctor/smoke test. لا تثبت بدائل متكررة لـADB أو Appium لمجرد وجودها في الكتالوج.

## الفشل وإعادة المحاولة

أعد المحاولة فقط بعد تصنيف الفشل: جهاز غير متصل، جلسة مشغولة، عنصر غير موجود، timeout، crash، أو خطأ في الأداة. اجمع screenshot وUI dump وlogcat قبل إعادة تشغيل الخدمة. حدّد عدد المحاولات وسجّل كل محاولة؛ لا تكرر أوامر مدمرة تلقائيًا.
